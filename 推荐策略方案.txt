================================================================
dir-dump 目录推荐策略方案
================================================================
说明：本文档描述"右键按住 200ms 弹出轮盘"中目录推荐条目的生成策略，
      包含现状梳理、已暴露的缺口，以及拟新增的"结构相似推荐"方案。

----------------------------------------------------------------
一、现状
----------------------------------------------------------------
当前仅有一个策略：CurrentDirStrategy（显示名"基于当前目录推荐"），
见 strategies/current_dir_strategy.py。它按以下子块依次产出条目：

  1) parent（父目录）
     配置 include_parent，默认开；产出 ".."。
  2) frequent（当前目录下的深层子目录）
     配置 include_frequent_dirs，默认开，max_frequent_dirs 默认 8。
     取历史中"位于当前目录之下、层级 >= 2"的目录（直接子目录不再推荐，
     因为在资源管理器里本就直接可见），按 (频次, 时间) 排序。
  3) global（不在当前目录下的历史高频目录）
     配置 include_global_dirs，默认开，max_global_dirs 默认 4。
     取历史中不属于当前目录子树的目录，按频次排序。
  4) sibling（同级兄弟目录，可选）
     配置 include_siblings，默认关；recent_days 默认 5，max_siblings 默认 3。
     按"最近使用/最近修改"打分取父目录下的其它子目录。
  5) favorite（收藏目录）
     配置 include_favorites，默认开。

其它规则：
  - 按规范化路径（normcase + normpath）去重；
  - 命中 path_styles 时套用颜色/图案（不覆盖手动设置）；
  - 最终取前 12 项展示（main.py 中 items[:12]）；
  - 历史记录上限 HISTORY_MAX_ENTRIES = 100，仅存 path / time / count。

----------------------------------------------------------------
二、已暴露的问题（核心缺口）
----------------------------------------------------------------
2.1 新目录下推荐经常为空白（本次要补充的重点）
    现象：进入一个以前从未访问过的新目录，轮盘里往往只剩 ".."，
          有时再加几条收藏，几乎没有可跳转的推荐。
    原因：
      - frequent 依赖"历史里存在当前目录子树下的记录"，新目录必然为空；
      - global 数量少（默认 4），且与当前目录的局部结构无关，
        对"继续往下走"没有指导意义；
      - 这些目录结构其实与已访问过的目录高度相似，但现有逻辑只看
        "精确路径 / 路径前缀"，完全没有利用这种相似性。
    举例：已访问过
          D:\proj\2024-01-05\{src,doc,test}
          D:\proj\2024-02-11\{src,doc,test}
          首次进入 D:\proj\2024-03-20 时，虽然结构与前两者几乎一致，
          却给不出任何推荐。

2.2 匹配粒度太"死"
    只按字符串前缀匹配同一棵子树，跨项目 / 跨日期 / 跨客户等
    "同构目录"完全无法互相借鉴。

2.3 历史容量有限
    上限 100 条、且按最近插入优先，长期会丢掉早期但结构上有价值的样本。

----------------------------------------------------------------
三、新增策略：结构相似推荐（StructureSimilarityStrategy）
----------------------------------------------------------------
3.1 目标
    当某目录自身历史为空（或很少）时，用"已访问目录的结构模式"
    推测该目录下可能存在的子目录，填补频繁项缺失造成的空白。

3.2 结构签名（路径模板）
    把绝对路径按层级归一化，将"可变段"替换为占位符，得到模板：
      - 日期段：2024-01-05 / 20240105 / 2024.01.05 -> <date>
      - 版本段：v1.2.3 / V2 -> <ver>
      - 纯数字/编号：2024 / 001 / 12345 -> <num>
      - 名称规律：clientA/clientB -> <name>（可选，较激进）
    例：
      D:\proj\2024-01-05\src  ->  D:\proj\<date>\src
      D:\work\clientA\docs    ->  D:\work\<name>\docs

3.3 三类匹配（可叠加，按置信度加权）
    a) 同模板匹配
       新目录的模板 == 某历史目录的模板：
         - 若新目录就是该模板位置 -> 推荐历史中"该模板的子目录名"集合；
         - 若新目录位于该模板之下 -> 推荐同级/更深一层的常见子目录名。
    b) 兄弟结构扩散
       新目录的父目录模板 == 历史中某目录的父目录模板：
         借鉴其兄弟目录下的深层结构（例如都含 src/inc/test）。
    c) 名称模式匹配（兜底层）
       统计目录名分组（src / inc / doc / docs / test / bin / log / build / cfg ...）
       在历史"深层子路径"中出现的频次，跨项目通用地推荐这些常见子目录名。

3.4 候选生成与打分
    候选 = 由上述匹配得到的"子目录名"，拼接到新目录（或模板对应祖先）下；
    仅当该路径真实存在（os.path.isdir）时才作为条目输出。
    打分权重（示例）：
      score = 模板命中样本数 × 归一化频次 × 时间衰减(按 recent_days)
    输出字段沿用 DirectoryItem，category 建议新增 "structure"。

3.5 兜底
    模板与名称模式均未命中时，给出"全局高频子目录名"候选
    （如 src / doc / test / bin 等）中确实存在的项；仍无则交给收藏等原有块。

3.6 与现有策略的合并顺序
    建议顺序：parent -> frequent -> structure -> global -> sibling -> favorite，
    即把结构相似推荐作为 frequent 与 global 之间的补充层；
    因最终只取前 12 项，结构项需在 frequent 为空/稀少时才有机会展示。

----------------------------------------------------------------
四、拟新增配置项（strategies.structure_similarity）
----------------------------------------------------------------
  enabled            : bool  默认 true   是否启用
  max_struct_dirs    : int   默认 6      最多产出条数
  min_support        : int   默认 1      模板命中所需最少样本数（>1 更保守）
  name_based_enabled : bool  默认 true   是否启用"名称模式"兜底层
  time_decay_days    : int   默认 30     打分的时间衰减窗口
  allow_name_wildcard: bool  默认 false  是否把字母+数字名也视为可变段（较激进）

----------------------------------------------------------------
五、需要的数据支撑
----------------------------------------------------------------
现有 history 仅存 path / time / count，不足以支撑结构匹配。建议二选一：
  A) 扩展 history 条目：新增 signature（模板）与 children（子目录名列表）、
     在 add_history() 时顺带采集；
  B) 新增独立索引 struct_index：{signature -> {child_name: {count, last_time}}}，
     周期性由 history 构建，避免改动现有历史结构。
推荐 B，采样成本可控、且便于按签名聚合与持久化。

----------------------------------------------------------------
六、示例（效果预期）
----------------------------------------------------------------
场景：历史已含 D:\proj\<date>\{src,doc,test} 的多条样本。
新进入 D:\proj\2024-03-20（无自身历史）：
  - 现有策略：frequent 空；仅 ".." 与少量 global/收藏；
  - 新增结构策略：模板 D:\proj\<date> 命中，聚合出 src / doc / test，
    校验在当前目录下确实存在后，作为推荐项展示（category=structure）。

----------------------------------------------------------------
七、实现与接入要点
----------------------------------------------------------------
  1) 新增 strategies/structure_similarity.py，实现 DirectoryStrategy
     子类（name="structure_similarity"，display_name="结构相似推荐"）；
  2) 在 strategies/registry.py 的 get_registry() 中注册；
  3) 模板/名称识别的公共逻辑（日期、版本、编号、名称分组）建议放在
     utils/patterns.py，便于复用与单测；
  4) 在 config/config_manager.py 的 DEFAULT_CONFIG 增加上述
     structure_similarity 配置块；
  5) 排序与去重沿用现有规则（规范化路径去重、items[:12]）。
